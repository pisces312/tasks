# 多语言（i18n）约定

fork **只维护英文与简体中文**两种语言：新增或修改字符串只加 `values/` 与 `values-zh-rCN/` 两处，
**不为其它语言补翻译**。未翻译的语言自动回退英文，这是预期行为，不是缺陷。

## 改哪里

| 资源 | 英文 | 简体中文 |
|---|---|---|
| Android app 字符串 | `app/src/main/res/values/strings.xml` | `app/src/main/res/values-zh-rCN/strings.xml` |
| KMP / Compose 字符串 | `kmp/src/commonMain/composeResources/values/strings.xml` | `kmp/src/commonMain/composeResources/values-zh-rCN/strings.xml` |

上游自带的多语言目录照收（合上游时不要删已有的 `values-xx`），只是**不再新增**翻译。

## 新增字符串的流程

1. 英文加到 `values/`（key 与上游风格一致：`git_sync_*`、`export_settings_*`、`import_settings_*`）。
2. 简体中文加到 `values-zh-rCN/`。
3. 不要把同一 key 加到其它 `values-xx`；也不要只加中文不加英文（英文是回退基准）。

## 已知缺口

- `git_sync*`（Git 同步界面）在 `values-zh-rCN` 里没有任何条目，中文环境下显示英文。
  合并前后一致，属于未补的定制文案，不是回归。

## 与上游的差异点

上游在 `app/src/main/res/` 与 `kmp/src/commonMain/composeResources/` 用符号链接做旧语言码
（`values-in → values-id`、`values-iw → values-he`）。仓库只保留 `values-id` / `values-he`，
每次合并后要检查并清理被 git 重新生成的 9 字节残留文件，详见
[`upstream-merge-conventions.md`](upstream-merge-conventions.md) 5.7。
